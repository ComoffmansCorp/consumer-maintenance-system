# Yandex Maps — ключи для автокомплита адреса

**Статус: реализовано** (2026-07-14, фаза 2 маркетплейса). Автокомплит адреса
на форме заявки (`/marketplace/new-request`) — печатаешь «сам», предлагает
«Самара, ...». Без визуальной карты (осознанный выбор для MVP). Код:
`frontend/src/composables/useYandexSuggest.ts`.

## Реализация — API Геосаджеста (HTTP), не JS API

Изначально предполагалось грузить `ymaps.SuggestView` из классического JS
API — но у пользователя нашёлся отдельный продукт **«API Геосаджеста»**
(`suggest-maps.yandex.ru/v1/suggest`), который делает ровно то же самое
через обычный HTTP GET, без загрузки тяжёлого JS SDK, с лимитом **1000
запросов/сутки** (у JS API — только 100/сутки). Переключились на него —
собственная выпадашка подсказок в стиле проекта вместо виджета Яндекса.
Контракт подтверждён по официальной документации (не угадан):
```
GET https://suggest-maps.yandex.ru/v1/suggest?apikey=<key>&text=<query>&print_address=1
→ { results: [{ title: {text}, address: {formatted_address}, uri, ... }] }
```

Координаты эта API НЕ возвращает — для них нужен отдельный ключ **HTTP
Geocoder** (`geocode-maps.yandex.ru/1.x/`), опциональный: если ключа нет,
адрес всё равно сохраняется как текст, просто без `latitude`/`longitude`.

## Ключи (уточнено на реальном кабинете, 14.07.2026)

Пользователь оформил три разных продукта — все выдаются отдельными ключами:

| Продукт | Лимит (бесплатно) | Используется сейчас |
|---|---|---|
| **API Геосаджеста** | 1000 запросов/сутки | ✅ Да — основной механизм автокомплита |
| **HTTP Geocoder** | — (см. кабинет) | ✅ Да — координаты по выбранной подсказке |
| **JavaScript API** | 100 запросов/сутки | ⛔️ Не используется — годится, если позже понадобится визуальная карта (см. открытый вопрос в плане маркетплейса) |

## ⚠️ Ограничение по HTTP referer/IP

Кабинет Яндекса требует настройки referer/IP-ограничения для ключей — на
момент оформления статус был «Не настроен». Для localhost-разработки не
критично, но **до любого публичного деплоя обязательно настроить** в личном
кабинете (ключи по природе видны в браузере — не серверный секрет, но без
ограничения ими может воспользоваться кто угодно, кто их увидит).

## Куда положены ключи

`frontend/.env` (НЕ коммитится, см. `.gitignore`):
```
VITE_YANDEX_GEOSUGGEST_API_KEY=<значение>
VITE_YANDEX_GEOCODER_API_KEY=<значение, опционально>
```
Шаблон без значений — `frontend/.env.example` (коммитится). Сами значения
ключей нигде в git/памяти/заметках не хранятся — только в локальном `.env`.

## Как это работает (реализовано)

`useYandexSuggest()` (composable):
1. Без `VITE_YANDEX_GEOSUGGEST_API_KEY` — `available = false`, поле адреса
   остаётся обычным текстовым без подсказок. Без падений.
2. С ключом — на каждый ввод (с debounce 300мс, чтобы не жечь суточный
   лимит на каждую букву) делает `fetch` к API Геосаджеста, показывает
   список подсказок под полем (собственная вёрстка, не виджет Яндекса).
3. При выборе подсказки — если задан `VITE_YANDEX_GEOCODER_API_KEY`,
   резолвит `uri` подсказки (или текст, если `uri` нет) через Geocoder и
   достаёт координаты. Без гео-ключа или при сбое запроса — сохраняется
   только текст адреса, без координат (best-effort, не блокирует отправку).
4. Ручное редактирование текста после выбора подсказки сбрасывает
   координаты (текст мог разойтись с геокодированной точкой) и заново
   запускает поиск подсказок.

## Референс API

https://yandex.ru/dev/geosuggest/doc/ru/ (API Геосаджеста, контракт
подтверждён 14.07.2026) и https://yandex.ru/dev/geocode/doc/ru/ (HTTP
Geocoder). Яндекс периодически переносит доки между поддоменами.
